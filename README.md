# ร้านของเบนซ์ v1.4 — ระบบสั่งอาหารล่วงหน้า + หลังร้าน

เว็บแอปสำหรับร้านอาหารขนาดเล็ก ใช้ฟรีได้ด้วย **GitHub Pages** (หน้าเว็บ) + **Firebase** (ฐานข้อมูลและระบบล็อกอิน)

| หน้า | ลิงก์ (หลังติดตั้งเสร็จ) | ใครใช้ |
|---|---|---|
| หน้าสั่งอาหาร | `https://<ชื่อ GitHub>.github.io/<ชื่อ repo>/` | ลูกค้า (สแกน QR หรือกดลิงก์ ไม่ต้องล็อกอิน) |
| หลังร้าน | `https://<ชื่อ GitHub>.github.io/<ชื่อ repo>/admin.html` | เจ้าของร้าน / พนักงาน |

## สิ่งที่ทำได้ในเวอร์ชันนี้

รูปแบบร้าน: **สั่งล่วงหน้า แล้วร้านนำไปส่งเองที่ทำงาน** (เช่น สั่งวันนี้ ได้กินพรุ่งนี้)

**ลูกค้า:** เข้ามาเจอเมนูเลย → เลือกเมนูใส่ตะกร้าได้หลายรายการ (สั่งแทนเพื่อนได้ ใส่ชื่อคนกินในช่อง "สั่งให้ใคร") → ตะกร้า → กรอกชื่อ (+เบอร์โทร) วันที่รับอาหาร และจุดส่ง → **ชำระเงิน: สแกน QR/โอนเข้าบัญชี แล้วแนบสลิป** → ยืนยัน → ได้เลขที่ออเดอร์และดูสถานะอัปเดตสด · ถ้าร้านเปิด "จ่ายทีหลัง" ลูกค้าแนบสลิปภายหลังได้จากหน้าติดตามออเดอร์ · กดหัวใจเก็บเมนูโปรด · สั่งซ้ำออเดอร์เก่า

**หลังร้าน:**
- ภาพรวม: ออเดอร์วันนี้ ยอดขายวันนี้/เดือนนี้ กำไรเดือนนี้ ออเดอร์รอดำเนินการ สำเร็จวันนี้ วัตถุดิบใกล้หมด
- ออเดอร์ใหม่เข้า: เด้งแจ้งเตือน + เสียง + ตัวเลขบนกระดิ่ง
- **การชำระเงิน:** ทุกออเดอร์มีสถานะ ยังไม่จ่าย / แนบสลิปแล้ว รอตรวจ / จ่ายแล้ว · เปิดดูรูปสลิปแล้วกด "ยืนยันรับเงินแล้ว" · ลูกค้าแนบสลิปเข้ามาจะเด้งแจ้งเตือน
- **ต้นทุนและกำไรต่อเมนู (ประมาณ):** หน้าบัญชี คำนวณจาก "ของที่ซื้อเข้า ÷ จำนวนที่ขายออก" ในช่วง 30 วัน / 3 เดือน / ปีนี้ ไม่ต้องชั่งตวงสูตร · ตอนบันทึกรายจ่ายให้เลือก "ใช้กับเมนูไหน" (เช่น บิสกอฟ → พายบิสกอฟ) รายจ่ายที่ใช้ร่วม (กล่อง แก๊ส) ระบบแบ่งตามสัดส่วนยอดขาย
- **เพิ่มออเดอร์เอง** (ลูกค้าสั่งปากเปล่า/ทักแชท): ปุ่ม "เพิ่มออเดอร์" ในหน้าออเดอร์และหน้าเตรียม & ส่งของ เลือกเมนู ตัวเลือก จำนวน ชื่อคนกิน และตั้งว่าจ่ายแล้ว/ยังไม่จ่าย (เงินสด/โอน) แนบสลิปแทนลูกค้าได้
- จัดการออเดอร์ 5 สถานะ (รอดำเนินการ → กำลังจัดเตรียม → พร้อมส่งมอบ → สำเร็จ / ยกเลิก) ดูแยกตามวันที่ส่ง · พิมพ์ใบเสร็จ
- **เตรียม & ส่งของ:** เลือกวันส่ง → เห็นจำนวนที่ต้องทำแต่ละเมนู/ตัวเลือก, วัตถุดิบที่ต้องใช้เทียบสต็อก (ขาดเท่าไร), รายการส่งแยกตามจุดส่งพร้อมยอดเงินที่ต้องเก็บ, ปุ่มรับ/ทำเสร็จทีเดียวทั้งหมด และพิมพ์ใบจัดส่ง
- จัดการเมนู หมวดหมู่ ตัวเลือก/ท็อปปิ้ง ราคา รูป และปิด "หมดแล้ว"
- สต็อกวัตถุดิบ: **ตัดสต็อกอัตโนมัติตามสูตรเมื่อออเดอร์ "สำเร็จ"** (ยกเลิกทีหลังระบบคืนสต็อกให้)
- บัญชี: รายรับจากออเดอร์ + บันทึกรายจ่าย (เลือกให้เพิ่มเข้าสต็อกได้) → กำไรวัน/สัปดาห์/เดือน/ปี + กราฟ
- วิเคราะห์ยอดขาย: รายวัน รายสัปดาห์ รายเดือน เมนูขายดี
- รายงาน Excel / พิมพ์เป็น PDF: ยอดขายรายวัน รายเดือน รายจ่าย สต็อก กำไร-ขาดทุน
- QR Code ของร้าน: ดาวน์โหลด PNG ไปส่งในกลุ่ม LINE หรือพิมพ์ติดไว้ · คัดลอกลิงก์
- ตั้งค่า: ส่งเร็วสุดกี่วัน, เวลาปิดรับของรอบนั้น, เลือกวันล่วงหน้าได้กี่วัน, วันที่ไม่ส่ง, จุดส่งที่ใช้บ่อย · ชื่อร้าน โลโก้ สีธีม ช่องทางติดต่อ · เปิด/ปิดรับออเดอร์ · พนักงาน (Owner / Staff) · สำรองข้อมูล
- โหมดมืด

## ขั้นตอนติดตั้ง (ประมาณ 30 นาที)

### ขั้นตอนที่ 1 — สร้างโปรเจกต์ Firebase
1. เข้า https://console.firebase.google.com ล็อกอินด้วย Gmail ของร้าน
2. กด **Create a project** (หรือ Add project) ตั้งชื่อ เช่น `benz-shop` → Google Analytics ปิดได้ → สร้าง

### ขั้นตอนที่ 2 — เปิดฐานข้อมูลและระบบล็อกอิน
1. เมนูซ้าย **Build › Firestore Database** → **Create database**
   - ถ้ามีให้เลือก Edition ให้เลือก **Standard**
   - Location: เลือก `asia-southeast1 (Singapore)` (ใกล้ไทย เปลี่ยนภายหลังไม่ได้)
   - เลือก **Start in production mode** → Create
2. เมนูซ้าย **Build › Authentication** → **Get started** → แท็บ Sign-in method → เปิด **Email/Password** → Save
3. แท็บ **Users** → **Add user** → ใส่อีเมลเจ้าของร้าน + รหัสผ่าน (อย่างน้อย 6 ตัว) → นี่คือบัญชีเข้าหลังร้าน

### ขั้นตอนที่ 3 — เอาค่าเชื่อมต่อมาใส่ในไฟล์
1. กดรูปเฟือง ⚙ ข้าง Project Overview → **Project settings**
2. เลื่อนลงหา **Your apps** → กดไอคอน `</>` (Web) → ตั้งชื่อ → Register app (ไม่ต้องติ๊ก Hosting)
3. จะเห็นโค้ด `const firebaseConfig = { apiKey: "...", ... }`
4. เปิดไฟล์ **`js/config.js`** (ใช้ Notepad ได้) แล้วคัดลอกค่าแต่ละบรรทัดมาแทน `ใส่_..._ที่นี่`
5. ในไฟล์เดียวกัน แก้ `OWNER_EMAIL` เป็นอีเมลเจ้าของร้าน (ตัวพิมพ์เล็กทั้งหมด)

> ค่า apiKey ของ Firebase ไม่ใช่รหัสลับ เปิดเผยบน GitHub ได้ตามปกติ ความปลอดภัยของข้อมูลมาจาก Rules ในขั้นตอนถัดไป

### ขั้นตอนที่ 4 — ใส่กฎความปลอดภัย (สำคัญมาก)
1. เปิดไฟล์ **`firestore.rules`** แก้บรรทัด `ownerEmail()` เป็นอีเมลเจ้าของร้าน (ตัวพิมพ์เล็ก ให้ตรงกับขั้นตอนที่ 3)
2. Firebase Console › Firestore Database › แท็บ **Rules** → ลบของเดิมทั้งหมด → วางเนื้อหาไฟล์ `firestore.rules` ทั้งไฟล์ → **Publish**

กฎนี้ทำให้: ลูกค้าสั่งอาหารได้โดยไม่ต้องล็อกอิน แต่ดูออเดอร์ของคนอื่น ยอดขาย หรือรายจ่ายไม่ได้ · พนักงานเห็นเฉพาะงานหน้าร้าน · เจ้าของร้านเห็นทุกอย่าง

### ขั้นตอนที่ 5 — อัปโหลดขึ้น GitHub และเปิดเว็บ
1. สมัคร/ล็อกอิน https://github.com
2. มุมขวาบน **+ › New repository** → ตั้งชื่อ เช่น `benz-shop` → เลือก **Public** → Create repository
3. ในหน้า repo ที่ว่าง กดลิงก์ **uploading an existing file**
4. แตกไฟล์ zip แล้ว **ลากไฟล์และโฟลเดอร์ทั้งหมดข้างใน** (`index.html`, `admin.html`, `css`, `js`, …) ไปวาง → กด **Commit changes**
   - ตรวจให้ `index.html` อยู่ชั้นนอกสุดของ repo ไม่ได้ซ้อนอยู่ในโฟลเดอร์อื่น
5. แท็บ **Settings › Pages** → Source: **Deploy from a branch** → Branch: `main` / `(root)` → Save
6. รอ 1–2 นาที รีเฟรชหน้า Pages จะเห็นลิงก์ `https://<ชื่อ>.github.io/benz-shop/`
7. (แนะนำ) Firebase › Authentication › Settings › **Authorized domains** → Add domain → `<ชื่อ>.github.io`

### ขั้นตอนที่ 6 — เริ่มใช้งานครั้งแรก
1. เปิด `.../admin.html` → ล็อกอินด้วยบัญชีจากขั้นตอนที่ 2
2. หน้าภาพรวมจะมีปุ่ม **สร้างข้อมูลเริ่มต้น** → กด (ได้หมวดหมู่ 2 หมวด, 6 เมนู: สุกี้โรล 60, กรีกโยเกิร์ตเปล่า 39, Banoffee Greek Pie 89, Banana Biscoff Pie 89, Biscoff Pie 79, Oreo Greek Pie 69 และวัตถุดิบ 8 รายการ)
3. ไปหน้า **สต็อกวัตถุดิบ** → กด "ปรับสต็อก" › "นับจริง" ใส่ยอดคงเหลือจริง และกด ✎ ตั้ง "แจ้งเตือนเมื่อเหลือไม่เกิน"
4. ไปหน้า **เมนูอาหาร** → แก้ไข สุกี้โรล → เติมสูตรที่ยังว่าง (ดูหัวข้อถัดไป) และอัปโหลดรูป
5. หน้า **ตั้งค่าร้าน › การสั่งล่วงหน้าและจัดส่ง** → ตั้งค่าแล้วกดบันทึก:
   - ส่งเร็วสุด: ตั้งไว้ "วันถัดไป" (สั่งวันนี้ ได้พรุ่งนี้)
   - เวลาปิดรับ: เช่น 20:00 → สั่งหลัง 2 ทุ่ม จะได้รับวันถัดไปอีกวัน (เว้นว่าง = ไม่จำกัด)
   - วันที่ไม่ส่ง: เช่น เสาร์ อาทิตย์ (ตอนนี้ยังไม่ได้ติ๊กวันไหนไว้)
   - จุดส่งที่ใช้บ่อย: เช่น ชื่อแผนก/อาคาร/ชั้นในที่ทำงาน ลูกค้าจะกดเลือกได้เลย
   แล้วใส่เบอร์โทร LINE โลโก้ สีธีม ในส่วนข้อมูลร้าน
   - **การชำระเงิน:** อัปโหลดรูป QR รับเงิน (แคปจากแอปธนาคาร) และ/หรือใส่ธนาคาร เลขบัญชี ชื่อบัญชี → กด "บันทึกการชำระเงิน" (ถ้ายังไม่ใส่ ระบบจะให้ลูกค้าจ่ายตอนรับไปก่อน)
6. หน้า **QR Code** → ดาวน์โหลดรูป QR ไปส่งในกลุ่ม LINE ที่ทำงาน หรือกดคัดลอกลิงก์
7. ลองสั่งจากมือถือ 1 ออเดอร์ แล้วดูว่าหลังร้านเด้งแจ้งเตือน (กดหน้าจอหลังร้าน 1 ครั้งก่อน เบราว์เซอร์ถึงยอมให้มีเสียง)

**ใช้งานประจำวัน:** ตอนเย็น/เช้าเปิดหน้า **เตรียม & ส่งของ** เลือก "พรุ่งนี้" หรือ "วันนี้" → กด "รับออเดอร์ทั้งหมด" → ดูจำนวนที่ต้องทำและวัตถุดิบที่ขาด → ทำเสร็จกด "ทำเสร็จทั้งหมด" → พิมพ์หรือเปิดรายการส่งติดตัวไป → ส่งถึงแต่ละคนกด "ส่งแล้ว" (ระบบตัดสต็อกและนับยอดขายตอนนี้)

**เพิ่มพนักงาน:** ตั้งค่าร้าน › พนักงาน › เพิ่มอีเมล แล้วไปสร้างรหัสผ่านให้อีเมลนั้นที่ Firebase › Authentication › Users › Add user

## ⚠ ข้อมูลที่ยังต้องกรอกเอง

ใส่ไว้ให้เฉพาะสูตรที่ได้รับมา: **สุกี้โรล 1 กล่อง = สาหร่าย 1 แผ่น, เต้าหู้ 1 ชิ้น, วุ้นเส้น 20 กรัม, อกไก่ 50 กรัม (เมื่อเลือกอกไก่)**

ยังไม่ได้ใส่ (เพราะไม่มีตัวเลข จึงไม่เดาให้):
- หมูเด้ง ใช้กี่กรัมต่อกล่อง
- น้ำจิ้มแต่ละแบบ ใช้เท่าไรต่อกล่อง (และหน่วยนับที่เหมาะ เช่น มล. แทน ขวด)
- ผักกาดขาว ใช้กี่กรัมต่อกล่อง
- กรีกโยเกิร์ต ยังไม่มีวัตถุดิบในสต็อก ถ้าต้องการตัดสต็อกให้เพิ่มวัตถุดิบ "กรีกโยเกิร์ต" แล้วใส่สูตร
- ยอดสต็อกเริ่มต้น จุดแจ้งเตือน และต้นทุนต่อหน่วย ตั้งไว้เป็น 0 ทั้งหมด

**หน่วยต้องตรงกัน:** ถ้าสูตรใช้ "ชิ้น" สต็อกต้องนับเป็นชิ้น เวลาซื้อเต้าหู้เป็นก้อนให้แปลงเป็นชิ้นตอนบันทึกเข้าสต็อก

## วิธีคิดตัวเลข

- **ยอดขาย** นับเฉพาะออเดอร์ที่สถานะ **สำเร็จ** และนับเข้า **วันที่ส่ง** (ไม่ใช่วันที่สั่ง) ต้องกด "ส่งแล้ว" ทุกออเดอร์ ไม่อย่างนั้นยอดไม่เข้า
- **เลขที่ออเดอร์** นับใหม่ทุกวันส่ง (#001, #002 … ของแต่ละวัน)
- **กำไร** = ยอดขาย − รายจ่ายที่บันทึกในหน้าบัญชี (ค่าวัตถุดิบนับตอนซื้อ ผ่านรายจ่าย)
- ถ้าเปลี่ยนราคาเมนูหลังลูกค้าสั่ง ระบบใช้ราคาตอนสั่ง และจะขึ้นคำเตือนในรายละเอียดออเดอร์ถ้าไม่ตรงราคาปัจจุบัน

## ข้อจำกัดที่ควรรู้

- **ตรวจสลิปด้วยตาเอง**: ระบบไม่ได้เช็กกับธนาคารอัตโนมัติ ต้องเปิดดูสลิปแล้วเทียบยอดเงินและเวลาในแอปธนาคารของร้านก่อนกด "ยืนยันรับเงินแล้ว" (สลิปปลอม/สลิปซ้ำเป็นไปได้)
- **ลูกค้าแก้ราคาเองได้ทางเทคนิค**: คนที่รู้เรื่องเว็บสามารถส่งออเดอร์ราคาผิดได้ ระบบจะขึ้นคำเตือน "ยอดรวมไม่ตรงกับราคาเมนู" ในรายละเอียดออเดอร์ ให้ดูก่อนรับเงิน
- **เสียงแจ้งเตือน** ดังเฉพาะตอนเปิดหน้าหลังร้านค้างไว้ในมือถือ/คอม ถ้าปิดหน้าไว้ ออเดอร์ยังเข้าระบบปกติ เปิดมาดูได้ทีหลัง
- **ประวัติออเดอร์ของลูกค้า / เมนูโปรด** เก็บในมือถือลูกค้าเครื่องนั้น ล้างเบราว์เซอร์แล้วหาย
- **แพ็กเกจฟรีของ Firebase (Spark)** มีโควตาอ่าน/เขียนข้อมูลต่อวัน ร้านขนาดเล็กใช้ไม่เกิน ตรวจการใช้งานได้ที่ Firebase › Usage and billing
- **รูปเมนู** ถูกย่อและเก็บในฐานข้อมูลโดยตรง (ไม่ใช้ Firebase Storage ซึ่งต้องผูกบัตรเครดิต) ใส่รูปได้ แต่ควรมีไม่เกิน ~30 เมนูที่มีรูป
- **สำรองข้อมูล**: ตั้งค่าร้าน › สำรองข้อมูลทั้งหมด (JSON) ยังไม่มีปุ่มกู้คืนอัตโนมัติ

## แก้ไขโค้ดภายหลัง
แก้ไฟล์บนเครื่อง แล้วอัปโหลดไฟล์ที่แก้ทับใน GitHub (Add file › Upload files) หน้าเว็บจะอัปเดตภายใน 1–2 นาที

## โครงสร้างไฟล์
```
index.html              หน้าสั่งอาหารของลูกค้า
admin.html              หลังร้าน
firestore.rules         กฎความปลอดภัยฐานข้อมูล
css/                    หน้าตา (app, customer, admin)
js/config.js            ค่าเชื่อมต่อ Firebase + อีเมลเจ้าของร้าน  ← แก้ไฟล์นี้
js/fb.js                เชื่อม Firebase
js/common.js            ฟังก์ชันใช้ร่วม
js/customer.js          ระบบหน้าลูกค้า
js/seed.js              ข้อมูลเริ่มต้น
js/admin/main.js        ล็อกอิน เมนู แจ้งเตือน
js/admin/state.js       ตัดสต็อก / สรุปยอดขาย
js/admin/views/*.js     แต่ละหน้าในหลังร้าน
```

## ฐานข้อมูล (Firestore collections)
`settings` ข้อมูลร้าน + การจัดส่ง + บัญชีรับเงิน · `slips` รูปสลิป (ดูได้เฉพาะพนักงาน) · `categories` หมวดหมู่ · `products` เมนู (ตัวเลือก + สูตร) · `orders` ออเดอร์ (มี deliveryDate, deliveryPoint) · `counters` เลขที่ออเดอร์ต่อวันส่ง · `daily` สรุปยอดขายตามวันส่ง · `inventory` สต็อก · `inventoryTx` ความเคลื่อนไหวสต็อก · `expenses` รายจ่าย · `staff` พนักงาน
